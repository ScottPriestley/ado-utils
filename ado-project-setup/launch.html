ADO Migration Launcher

Copies an Azure DevOps project template — its process template, area & iteration paths, work items, queries, dashboards, and wiki — from one project into another. New here? Follow the four steps below in order — no scripting or Azure DevOps admin experience required.

Set up this PC (one time only)

Already done this on this computer? Skip to Open the launcher above.

  1. Open the link you were sent for the shared ADO Migration Launcher folder, then click Add shortcut to My files (or Sync) so it's added to your OneDrive.
  2. Make sure the folder has finished syncing from OneDrive — look for the green checkmark on the folder icon, not a blue spinning-sync icon.
  3. In File Explorer, open the synced ADO Migration Launcher folder — it's under OneDrive - HSO\Documents\ADO Migration Launcher.
  4. Right-click Setup.cmd and choose Run as administrator.
2

Requirements

The launcher checks each item and tells you immediately if something's missing or wrong.

  • Source project URL — the Azure DevOps project template you're copying from, e.g. https://dev.azure.com/{org}/{project}.
  • Source Organization PAT (Personal Access Token) — a temporary access token for the source project, with read access to Work Items, Process, Queries, Wiki, and Dashboards.
  • Target project URL — the project you're copying into. It usually needs to already exist — see Step 3 for the one exception.
  • Target Organization PAT — a temporary access token for the target project, with read & write access. You can generate this yourself if you already have access to the target organization; otherwise the customer's Azure DevOps Admin will need to create it for you.
  • Elevated permission in the target organization — only needed if you're using "Full automation" mode below (Step 3). The customer's Azure DevOps Admin needs to grant you Project Collection Administrator so the tool can create the process and the project. This can be granted temporarily and removed again as soon as the process and project have been created — it doesn't need to stay in place for the rest of the migration.
A PAT is a code Azure DevOps generates so tools like this one never see your real login. The launcher uses it only for this session — it's never saved to disk, written to a log, or stored anywhere.
3

Choose how the process template should be handled

Only matters if you're copying the process template (work item types, fields, states). Skipping the process template? Skip to Step 4.

Full automation

Easiest

The launcher creates the process and the target project for you, then continues straight into the rest of the copy automatically.

Choose this if: the target project doesn't exist yet and you have permission to create projects in the target organization.

Create the Process now, Create the Project later

The launcher creates the process, then pauses and asks you (or the customer's Azure DevOps admin) to create or switch the target project by hand — Azure DevOps has no way to do that automatically. Once that's done, come back and run the launcher again to finish.

Choose this if: someone else needs to create the target project, or you don't have permission to create one yourself.

Export the process template only

The launcher makes no changes at all — it just saves the process definition to a file you can hand off. Nothing else runs in that session, since a copy still needs a target project.

Choose this if: a customer's own admin will set up the target project and process themselves.
